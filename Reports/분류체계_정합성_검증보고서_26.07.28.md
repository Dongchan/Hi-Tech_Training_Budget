## 3. 예산 수치 오류 49건 — 유형별 원인

### S1. [심각] 6열 총괄표 시프트 오류 — 25건
추경란이 없는 부처의 총괄표(6열)를 7열로 가정하고 파싱하여 **값이 한 칸씩 밀림**.
`2025_supplementary←2026요구`, `2026_request←2026확정`, `2026_budget←증감액`이 들어갔다.

- 해당: id 7, 9, 10, 11, 12, 13, 14, 16, 240, 242, 243, 336, 337, 338, 339, 340, 341, 342, 343, 344, 346, 452, 453, 466, 467
- **2026 확정예산이 음수인 6건**(id 9, 243, 339, 452, 466, 467)은 전원 이 유형 — 감액 사업의 증감액(△)이 확정예산 자리에 기록됨
- 음수 6건만 PDF 실측값으로 보정해도 총계가 **+216,755백만원(약 +2,168억, +0.8%)** 달라짐: 27,079,917 → 27,296,672
- 나머지 시프트 건(양수라 눈에 띄지 않음)까지 보정하면 차이는 더 커짐 → **전량 재파싱을 v1.1 과제로 권고**

### S2. [중간] 증감액·증감률 누락/오기 — 20건
`change_rate=null`(% 부착 값 파싱 실패 추정) 또는 증감 필드 오기. 확정예산 자체는 정확.
- 해당: id 26, 34, 87, 88, 111, 118, 164, 170, 174, 255, 257, 290, 403, 413, 414, 430, 438, 444, 450, 527
- id 527은 리더 실측 판정: 2026확정 7,371은 유효, change_amount/rate만 텍스트 추출 순서 오류

### S3. [중간] 다행(多行) 총괄표 부분 파싱 — 3건
총괄표가 2개 행(예: 민간경상보조+사업출연금)인 사업에서 1개 행만 반영.
- id 66, 112, 316. 예: id 112(데이터기반산업경쟁력강화) 2026 실제 10,399 vs JSON 1,280 (1/8만 반영)

### S4. [경미] 신규사업 '순증' 표기 처리 — 1건 (id 281)

## 4. 분류체계 발견 사항

### S5. [심각] AI 도메인 분류의 부적절·누락 — 195건 (36.6%)
- **wrong 11건**: 핵심 도메인이 틀림. 예: id 86 네트워크 인프라 사업에 '교육/인재' 오부여, id 132 의료AI 사업에 '교육/인재' 오부여, id 120-122 디지털포용 '교육' 사업에 'LLM/언어모델' 부여(역으로 '교육/인재' 누락), id 131 휴머노이드 사업에 'LLM/언어모델'
- **partial 184건**: 일부 도메인 부적절 또는 명백한 누락
- 인재양성 관점 영향: '교육/인재' 도메인(66건, 6.82조)은 실질 인재양성 사업과 42건 누락 / 12건 오포함 차이 → 검증 반영 시 **96건, 7.87조** (별도 현황 보고서)

### S6. [심각] 분류체계 이원화 — 대시보드와 데이터의 분류가 다름
`js/cross-compare.js`는 build_db의 `ai_domains`(28종)를 무시하고 **자체 15개 도메인 키워드(DOMAIN_KEYWORDS)로 재분류**한다(주석: "ignore ai_domains from build_db"). 명칭 체계도 다름('교육\인재양성' vs '교육/인재'). **화면 간 도메인 집계가 상호 불일치**할 수 있는 구조.

### M4. [중간] 부처 내 코드-명칭 충돌 — program 7 / unit 25 / detail 78건
- 실제 오타: '인공지능**테**이터진흥'(2600), '정보통신산업융합'↔'정보통신융합산업'(2100) 등
- 회계구분 접미사 변형 혼재: 'AI경쟁력강화' vs 'AI경쟁력강화(일반)/(방발)' — 동일 사업의 표기 분열
- 코드는 부처 내에서만 유일한 체계임(전역 유일 아님)에 유의

### M5. [중간] 사업명 품질
- PDF 대비 전사 오류 3건: id 115(벤처**밸리**→벤처**벨리**), id 149('능동**행동**형'→'능동형'), id 164('첨단**원천**유망'→'원천' 누락)
- 사업명 잘림 15건(`…` 포함, ISSUE.md 주장 9건보다 많음), id 267 사업명에 널 문자(U+0000) 포함

## 6. 검증 무결성

- 1·2차 판정 일치율(재검 123건): 예산 120/123(97.6%), AI관련성 104/123(84.6%), 분류 97/123(78.9%), 인재양성 113/123(91.9%) — 수치 대조는 안정적, 의미 판단은 2차 판정을 최종 채택
- 정상 판정 추가 표본 독립 재검 11건(id 17, 67, 127, 177, 224, 275, 323, 377, 426, 478, 521 — 4개 판정 항목 × 11건 = 44개 비교): 전체 일치 38/44(86.4%). **예산 판정 11/11(100%)·인재양성 여부 11/11(100%) 완전 일치**, 불일치 6건은 전부 core/partial/none 경계의 의미 판단(AI 관련성 3, 도메인 분류 3)으로 본검증의 의미 판단 불확실성 범위와 일치 → 핵심 수치(예산·인재양성 목록)는 안정적, 분류·관련성 집계는 ±수 건 수준의 판정 편차를 전제할 것
- 리더 수동 PDF 실측: 페이지 오프셋 3건, 사업명 미확인 8건, id 527 총괄표 등 12건 이상

## 7. 활용 지침 및 후속 과제 (v1.1 제안)

**활용 지침**
1. 페이지 매핑·사업 목록·계층 구조는 그대로 신뢰하고 활용 가능
2. 예산 수치 인용 시 3절의 49건 목록을 먼저 대조할 것 (특히 음수 예산 6건은 사용 금지)
3. `ai_domains` 기반 집계는 ±30% 이상의 오차 가능성을 전제할 것; '교육/인재' 집계는 본 검증의 96건 목록으로 대체 권고
4. 대시보드 화면 간 수치 비교 시 분류 이원화(S6)에 유의

**후속 과제(v1.1)**
1. 6열 시프트 25건 + 다행 3건 전량 재파싱·보정 (기능별 분류 합계 행과 교차검증하면 자동화 가능)
2. `ai_domains` 재분류 (partial 184건 대상, 본 검증의 판정 근거 활용)
3. cross-compare.js 분류를 build_db 체계로 통일
4. 사업명 정정 3건, 널 문자 제거, 코드-명칭 충돌 오타 정정
