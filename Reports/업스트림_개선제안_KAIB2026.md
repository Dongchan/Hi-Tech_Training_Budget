## 제안 요약

533개 사업 전수를 원본 PDF(5,296p)와 대조 검증한 결과를 기반으로, 다음 5가지 개선을 제안한다.

### 1. 예산 필드 보정 49건 (budget_raw.json / budget_db.json)

- **6열 총괄표 시프트 25건**: 추경란이 없는 총괄표를 7열로 파싱해 값이 한 칸씩 밀림. 이로 인해 2026 확정예산이 음수인 사업 6건(id 9, 243, 339, 452, 466, 467) 발생. 수치 변경 19건 반영 시 2026 총계 27,079,917 → **27,548,563 백만원 (+468,646)**
- 증감액·증감률 누락/오기 20건('%'·'순증' 파싱 실패), 다행 총괄표 부분 파싱 3건, 기타 1건
- 확정값 데이터: `analysis/budget_corrections_v11.json` (사업별 7필드 + 근거 페이지·열 구조 note)

### 3. 내역사업(sub_projects) 보정 165건 + 컬럼 의미 문서화

- 재추출로 내역 행 685 → 820 (+135 복구: 페이지 경계 분리·누락·하위분류 혼입)
- **문서화 제안**: `sub_projects.budget_2024`는 내역표의 **예산액(추경)**, 모사업 `2024_settlement`는 **결산(집행액)** — 개념이 달라 합계가 원래 일치하지 않음을 Data-format.md에 명시 권장 (검증 시 108개 사업이 이 개념 차이로 "불일치"처럼 보임)
- 보정 데이터: `analysis/sub_projects_corrections_v12.json`
- 참고: PDF 원본 자체 불일치도 발견됨 (2025년 모예산≠내역표 19건, 표 내부 합계 불일치 4건 — 예: id 142 합계행 3,328 vs 내역행 합 3,228)

### 4. 분류체계 이원화 해소 (cross-compare.js)

`js/cross-compare.js`의 `DOMAIN_KEYWORDS`(자체 15개 도메인)가 build_db의 `ai_domains`(28종)를 무시하고 재분류하여("Recompute domain budget using DOMAIN_KEYWORDS only" 주석) 화면 간 집계가 불일치할 수 있음. build_db 체계로 단일화 권장.
- 참고 데이터: `analysis/ai_domains_revised.json` — 28종 체계 내 재분류 195건 (예: 디지털배움터 3건 'LLM/언어모델'→'교육/인재')

### 5. 문서-데이터 정합 (Data-format.md)

- 도메인 27종(문서) vs 28종(실측, '기타' 포함) / 중복 그룹 97(문서) vs 102(실측)
- metadata의 2025 총계가 '추경 우선' 합산임을 명시 권장
